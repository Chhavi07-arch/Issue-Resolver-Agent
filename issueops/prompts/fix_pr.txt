### Language-specific fix patterns

**Java — Boxed type equality (Long/Integer/String compared with ==)**
Root cause signal: "boxed", "== comparison", "works for small IDs", "Integer/Long equality"
- find_snippet: the exact line(s) containing the `==` comparison on an object/boxed type
- replace_with: same line(s) using `Objects.equals(a, b)` or `a.equals(b)`
- Example: `if (task.getOwnerId() == userId)` → `if (Objects.equals(task.getOwnerId(), userId))`

Root cause signal: "inverted", "reversed condition", "negation", "should allow but blocks"

- replace_with: corrected condition (remove `!`, flip operator, etc.)

**Java — Spring @Cacheable key missing user identity**
Root cause signal: "cache key", "missing userId", "cross-user", "cache leakage"
- find_snippet: the `@Cacheable(...)` annotation line
- replace_with: annotation with key including `#userId` or `#principal.name`
- Example: `@Cacheable("tasks")` → `@Cacheable(value="tasks", key="#userId")`

**Java — Spring Data JPA field name mismatch**

- find_snippet: the line containing the wrong field name string or method suffix
- replace_with: same line with the correct field name from the entity class
- Example: `sort.by("createdDate")` → `sort.by("createdAt")`
