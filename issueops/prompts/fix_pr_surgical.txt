## How to generate the edit

**Step 1 — Locate the bug.**
Using the root cause and fix strategy above, find the specific lines in the file
that implement the described faulty logic. Look at function bodies, condition
expressions, return statements, and annotations matching the root cause.

**Step 2 — Select the minimal line range.**
Choose the fewest consecutive lines (1–8 lines) that contain the bug.
Record start_line and end_line from the NNN | line-number prefix.

**Step 3 — Write replace_with.**
Write the corrected replacement for lines start_line through end_line.
- Include ALL lines in the selected range (both changed and unchanged lines).
- Do NOT include the NNN | prefix — code content only.
- Preserve exact indentation character-for-character.
- Make only the change the root cause requires. Nothing else.

**Step 4 — Self-check.**
Your replace_with MUST differ from the original code at those line numbers.
If the replacement is identical to the original, you found the wrong location —
go back to Step 1 and look again.

## Hard Constraints

- You MUST include at least one edit in `edits`. An empty list is a failure.
- Only modify the file shown above. Do not invent or guess other file paths.
- Maximum 1 edit entry, maximum 8 lines per edit.
- replace_with must be syntactically complete (balanced braces, correct indentation).
- replace_with contains code only — no NNN | prefixes, no prose, no markdown.

## Output fields

**patch_plan**: One sentence — which line(s) change and why this fixes the root cause.

**edits**: Exactly one LineAnchoredEdit with:
  - path: the file path shown above
  - start_line: first line of the bug block (from NNN | prefix)
  - end_line: last line of the bug block (from NNN | prefix)
  - replace_with: corrected code for that line range
  - change_summary: one sentence describing the change

**confidence**: 0.5–1.0. This mode always produces an edit, so confidence floor is 0.5.
  - 0.9+ exact bug location confirmed, fix is unambiguous
  - 0.75 location found, fix is the most likely correct change
  - 0.5  best available fix given visible context

**validation_notes**: Brief note or empty string.

**ready_for_pr**: true
