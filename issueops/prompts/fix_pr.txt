## How to generate the edit

Follow these steps in order. Do not skip steps.

**Step 1 — Locate the bug.**
In the file contents above, find the lines that contain the code described in the
root cause. Note their line numbers from the "NNN | " prefix.

**Step 2 — Select the smallest contiguous block.**
Choose the fewest consecutive lines that contain the complete bug.
- The block must be contiguous: no skipping intermediate lines.
- Do not cross function or class boundaries unless the bug spans them.
- Record the range as source_lines, e.g. "23-27".

**Step 3 — Copy find_snippet verbatim.**
Transcribe those lines CHARACTER-FOR-CHARACTER from the file above.
- Remove the "NNN | " prefix from each line. Copy everything else exactly.
- Do not retype from memory. Do not paraphrase. Do not reformat.
- Do not merge lines from different parts of the file into a single snippet.

**Step 4 — Write replace_with.**
Replace only the lines that need to change.
- Lines in find_snippet that are unchanged must appear IDENTICALLY in replace_with.
- Preserve indentation, spacing, and line endings.
- Make only the change the root cause requires — nothing else.

**Step 5 — Verify before finalising.**
Re-read find_snippet character by character against the file lines at source_lines.
If any character differs, DISCARD this edit entirely.
Do not include it in proposed_edits. Set ready_for_pr=false instead.

## Rules

**find_snippet**
- Must be copied verbatim from the file (Step 3 above).
- Must be a single contiguous block from one location.
- Length: 1–15 lines. If the bug cannot be fixed within 15 lines, investigate further.
- If the exact text is not visible in the file contents above, do NOT include the edit.

**replace_with**
- Minimal: only change the lines that fix the bug.
- Must be syntactically complete (balanced braces, correct indentation).
- Must not introduce unrelated refactoring or style changes.

**files**
- Only modify files shown in "Relevant File Contents" above.
- Do not invent or guess file paths.
- Maximum 2 files. If the fix requires only 1 file, use only 1.

**When to produce no edits**
Set proposed_edits=[], ready_for_pr=false, confidence<0.5 when ANY of these are true:
- The bug is not visible in the provided file contents.
- You cannot identify exact lines to replace (Step 5 verification fails).
- The fix requires runtime state, external config, or information not shown.
- The root cause is ambiguous and no specific change can be identified.

Producing no edit is correct and safe. Producing a hallucinated or reconstructed
edit is worse than producing none — it will fail patch application or corrupt the file.

## Output fields

**patch_plan**: 2-3 sentences — what changes, in which file, why it fixes the root cause.

**confidence**: how certain you are this edit is correct and complete.
- 0.9+  exact fix, location confirmed in file contents
- 0.75  likely correct, location found, minor uncertainty about side effects
- 0.5   plausible but edge cases possible
- <0.5  insufficient grounding — set ready_for_pr=false, proposed_edits=[]
