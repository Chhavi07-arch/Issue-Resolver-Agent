### Language-specific patterns to check

Scan the file contents above for these common but subtle bugs before concluding.

**Java (Spring Boot)**
- Boxed type equality: comparing `Long`, `Integer`, or `String` with `==` instead of `.equals()`.
  Java caches boxed values only for -128 to 127 — objects outside that range fail `==` even when
  the values are equal. Symptom: logic works for small IDs (≤127) but breaks for larger ones.
  Fix: replace `a == b` with `Objects.equals(a, b)` or `a.equals(b)` for boxed/object types.
- Inverted condition: an ownership or authorization guard that uses `!` when it shouldn't,
  or a null check that is reversed. Look for `if (!ownerCheck)` or `if (id != userId)` patterns.
- @Cacheable key scope: `@Cacheable(key="#param")` that omits user/session identity returns
  the same cached value to all callers. Symptom: one user sees another user's data intermittently.
  Fix: include `#userId` or `#principal.name` in the key expression.
- Spring Data JPA field mismatch: method names like `findByCreatedDate` or sort parameters like
  `sort=createdDate` must exactly match entity field names. "No property 'X' found for type 'Y'"
  means field X does not exist on entity Y — check the entity class for the correct field name.
- Transaction boundaries: `@Transactional` missing on a service method that calls multiple
  repository operations, or lazy-loading a collection outside a transaction.

**Python**
- Mutable default argument: `def f(items=[])` — the list is shared across all calls.
  Fix: `def f(items=None): items = items or []`
- Missing await: calling a coroutine without `await` returns a coroutine object, not the result.
- Truthiness edge cases: `if x:` is False for 0, empty string, empty list — use explicit checks.

**Node.js / TypeScript**
- Unhandled Promise: missing `await` or `.catch()` on an async operation silently swallows errors.
- Shared mutable singleton: module-level objects (caches, counters) mutated per-request cause
  cross-request state bleed in long-running servers.
