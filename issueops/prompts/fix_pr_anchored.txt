## How to generate the edit (Mode B — line-anchored)

Follow these steps in order. Do not skip steps.

**Step 1 — Locate the bug.**
In the file contents above, find the lines that contain the code described in the
root cause. Identify their line numbers from the "NNN | " prefix.

**Step 2 — Select the smallest contiguous line range.**
Choose the fewest consecutive lines that fully contain the bug.
- Record start_line and end_line (both 1-based, inclusive) from the NNN | prefix.
- The range must be contiguous — no skipping intermediate lines.
- Do not cross function or class boundaries unless the bug spans them.

**Step 3 — Write replace_with.**

- Preserve original indentation, spacing, and line endings exactly.

**Step 4 — Verify before finalising.**
Re-read your replace_with against the file lines at start_line through end_line.
Only the bug lines should differ. Unchanged lines must be identical.

## Rules

**start_line / end_line**
- Must be exact line numbers from the NNN | prefix in the file listing above.
- Must refer to a contiguous block from a single location.
- Range: 1–15 lines. If more lines are needed, investigate the narrowest possible fix.
- If the relevant lines are not visible in the file contents above, do NOT include the edit.

**replace_with**
- Contains all lines in the selected range (start_line to end_line), with the bug fixed.
- Minimal change: only the lines needed to fix the bug should differ from the originals.
- Must be syntactically complete (balanced braces, correct indentation).
- Must not introduce unrelated refactoring or style changes.

**files**
- Only modify files shown in "Relevant File Contents" above.
- Do not invent or guess file paths.
- Maximum 2 files. If the fix requires only 1 file, use only 1.

**Before giving up — look harder**
If the relevant file is shown and the root cause describes observable code patterns
(wrong variable name, missing condition, incorrect operator, off-by-one index,
wrong method call, inverted boolean, missing null check, etc.), you should be able
to identify line numbers and produce an edit. Re-read the root cause and scan the
numbered file listing again before deciding nothing is visible.

**When to produce no edits**
Set edits=[], ready_for_pr=false, confidence<0.5 ONLY when ALL of these are true:
- You have re-read the root cause and scanned the full numbered listing above.
- The specific bug lines are genuinely not visible (wrong file, truncated past the bug, etc.).
- The fix requires runtime state, external config, or information not shown above.
- No specific line range can be identified with confidence >= 0.5.

Producing no edit is a last resort. Producing an incorrect line range or a hallucinated
replacement is worse than producing none — but exhausting your search first is required.
